# AppForge v0.2.0

Release date: March 28, 2026

## Summary

`v0.2.0` adds supported multi-provider orchestration to AppForge. The app can now route prompts through a single configured provider or an ensemble of configured providers, merging their compact scaffold blueprints into one deterministic plan.

## Highlights

- `Single` and `Ensemble` routing modes for OpenAI, Anthropic, Ollama, and LM Studio
- Parallel planning requests across enabled providers with lead-provider tie-breaking
- Expanded settings UI for routing mode, lead-provider selection, per-provider readiness, and local-model discovery
- Clearer status surfaces in the header, sidebar, and conversation view
- Added hover tooltips on the main workspace controls and configuration flows

## Verification

The release candidate was verified with:

- `xcodegen generate`
- `xcodebuild -project AppForge.xcodeproj -scheme AppForge -showBuildSettings`
- `xcodebuild -project AppForge.xcodeproj -scheme AppForge -configuration Debug -destination 'platform=macOS,arch=arm64' build`
- Launch verification of the built `AppForge.app`

## Known Limitations

- Arbitrary prompts are still scaffold-first; the full autonomous multi-file coding loop is not complete yet.
- Cloud providers still use supported API-key authentication rather than browser-account session reuse.
- Xcode coding intelligence is not integrated into AppForge.
- iPhone, iPad, and watch app generation are not yet end-to-end.

## Upgrade Notes

- This release introduces bundle version `0.2.0 (2)`.
- Existing local workspaces under `~/AppForge` remain compatible.
- Existing provider settings are normalized on load so the lead provider and enabled-provider set stay consistent.
- Packaged app assets are local release builds and are not notarized yet.
